# Чекліст перед здачею

Цей файл містить короткий фінальний сценарій перевірки та перелік скриншотів для здачі роботи.

## 1. Перед запуском

Переконайтеся, що відкрито актуальну версію репозиторію.

Для командного рядка:

```text
dotnet restore OOP-ConsoleInputOutput-Lab2.sln
dotnet build OOP-ConsoleInputOutput-Lab2.sln
dotnet run --project OOPConsoleInputOutputLab2.csproj
```

У Visual Studio 2022 потрібно відкрити `OOP-ConsoleInputOutput-Lab2.sln` і запустити проєкт `OOPConsoleInputOutputLab2`.

## 2. Рекомендований набір скриншотів

### Скриншот 1 — головне меню

Після заставки натиснути Enter і зафіксувати меню:

```text
1. Перевірка року на високосність
2. Побудова числового трикутника
3. Гра «Хто хоче стати мільйонером?»
4. Калькулятор
0. Вихід
```

### Скриншот 2 — завдання 1

Ввести:

```text
2000
```

На екрані має бути:

```text
2000 рік є високосним.
```

За бажанням зробити додатковий скриншот із `1900`, щоб показати правило кратності 100.

### Скриншот 3 — завдання 2

Ввести висоту:

```text
4
```

На екрані має бути:

```text
      1
    2 2
  3 3 3
4 4 4 4
```

### Скриншот 4 — завдання 3, питання

Відкрити гру та зафіксувати одне питання разом із чотирма варіантами відповіді.

### Скриншот 5 — завдання 3, результат

Правильна послідовність для поточного набору питань:

```text
2
3
2
3
3
```

Фінальний результат:

```text
Ваш підсумковий рахунок: 500 із 500 балів.
```

### Скриншот 6 — завдання 4

Ввести саме приклад із завдання:

```text
5 + 5 * 10 + 4 / 2 - 3
```

Результат:

```text
54
```

Цей скриншот особливо важливий, оскільки він безпосередньо демонструє правильний пріоритет арифметичних операцій.

## 3. Що перевірити перед створенням скриншотів

- українські символи відображаються правильно;
- вікно консолі достатньо широке, щоб рядки не переносилися;
- на скриншоті видно заголовок поточного завдання;
- немає повідомлень про помилки середовища або компіляції;
- після кожного модуля Enter повертає до головного меню;
- для фінального скриншота калькулятора використано саме контрольний вираз із завдання.

## 4. Що передати викладачу

Відповідно до умов роботи достатньо:

- скриншотів виконання програми;
- посилання на GitHub-репозиторій **або** ZIP-архів проєкту.

Рекомендований варіант — посилання на GitHub і набір скриншотів.

## 5. Технічна контрольна перевірка

У репозиторії GitHub Actions автоматично перевіряє:

- solution і збірку в Release;
- відсутність попереджень компілятора;
- головне меню та помилки введення;
- правила високосного року;
- трикутники висотою 1, 4 і 10;
- результати гри 0, 100, 200 і 500 балів;
- основний приклад калькулятора;
- пріоритет і порядок арифметичних операцій;
- дробові числа;
- ділення на нуль;
- неправильний синтаксис;
- переповнення числового типу;
- відсутність залишених `TODO`, `FIXME` та старих заглушок у C#-коді.
