# План проєкту

## 1. Ідея

Один консольний застосунок C# об’єднує чотири навчальні завдання. Користувач запускає програму, бачить коротку заставку, переходить до головного меню, обирає завдання, виконує його та повертається до меню.

Основна мета — не зробити «складну систему», а показати якісну структуру, коректні алгоритми, зрозумілий код та охайну взаємодію з користувачем.

## 2. Принцип «простий, але на рівні»

Ми свідомо не будемо:
- створювати зайві шари архітектури;
- підключати сторонні пакети;
- використовувати БД, GUI або веб;
- приховувати алгоритми за готовими бібліотечними обчислювачами;
- робити код, який складно пояснити викладачу.

Ми будемо:
- розділяти відповідальність між невеликими класами;
- використовувати зрозумілі назви;
- перевіряти введення;
- уникати дублювання;
- тримати кожне завдання незалежним;
- додавати тести сценаріїв перед здачею.

## 3. Користувацький сценарій

1. Запуск програми.
2. Заставка.
3. Натискання Enter.
4. Головне меню:
   - 1 — високосний рік;
   - 2 — трикутник;
   - 3 — мільйонер;
   - 4 — калькулятор;
   - 0 — вихід.
5. Виконання обраного модуля.
6. Пауза та повернення до меню.
7. Завершення лише через пункт 0 або штатне закриття програми.

## 4. Архітектура

### Program.cs
Точка входу. Створює доступні завдання, показує заставку та запускає цикл головного меню.

### IConsoleTask
Мінімальний спільний контракт для всіх завдань:
- назва;
- метод виконання.

Це дає простий приклад поліморфізму без зайвого ускладнення.

### LeapYearTask
Містить тільки логіку першого завдання та взаємодію з користувачем для цього модуля.

### TriangleTask
Перевіряє висоту та будує центрований числовий трикутник.

### MillionaireTask
Керує грою з 5 питань. Дані одного питання зберігаються в моделі Question.

### CalculatorTask
Приймає арифметичний рядок, розбирає його та виконує операції з правильним пріоритетом.

### Question
Невелика модель:
- текст питання;
- 4 варіанти;
- номер правильної відповіді.

### ConsoleHelper
Тільки спільні дрібні операції:
- пауза;
- заголовки;
- безпечне читання цілого числа;
- повідомлення про помилку.

Не переносимо сюди алгоритми самих завдань.

## 5. Етапи реалізації

### Етап 0 — документація
- README;
- вимоги;
- архітектура;
- тестові сценарії.

### Етап 1 — каркас
- створити .NET console project;
- заставка;
- головне меню;
- цикл програми;
- заглушки чотирьох модулів;
- перевірка неправильного пункту меню.

### Етап 2 — високосний рік
Алгоритм:
- кратність 400 → високосний;
- інакше кратність 100 → не високосний;
- інакше кратність 4 → високосний;
- інакше → не високосний.

### Етап 3 — трикутник
Для рядка `i`:
- вивести відступ;
- вивести число `i` рівно `i` разів;
- повторити до заданої висоти.

Передбачити адекватний діапазон висоти, щоб користувач випадково не вивів тисячі рядків.

### Етап 4 — мільйонер
- 5 заздалегідь визначених питань;
- по 4 варіанти;
- лише 1 правильний;
- +100 балів за правильну відповідь;
- неправильна відповідь завершує гру;
- якщо всі 5 правильні — 500 балів та фінальне привітання.

### Етап 5 — калькулятор
Підтримка:
- цілих і, за можливості, десяткових чисел;
- `+`, `-`, `*`, `/`;
- пробілів у виразі;
- правильного пріоритету `*` і `/`.

Не використовувати готовий eval/DataTable.Compute.

Базова реалізація:
1. токенізація рядка;
2. перший прохід — `*` та `/`;
3. другий прохід — `+` та `-`;
4. перевірка ділення на нуль та некоректного синтаксису.

Дужки не входять до обов’язкового завдання і не додаються в першу версію.

### Етап 6 — фінальна перевірка
- build без помилок;
- ручні тести;
- перевірка українського тексту;
- перевірка кодування UTF-8;
- скриншоти для здачі;
- фінальний README.

## 6. Git-стратегія

Основна гілка: `main`.

Роботу можна вести невеликими логічними комітами:
- `docs: add project plan`
- `feat: add application shell and menu`
- `feat: implement leap year task`
- `feat: implement triangle task`
- `feat: implement millionaire game`
- `feat: implement calculator`
- `test: verify console scenarios`
- `docs: add final usage instructions`

Для навчального проєкту окрема гілка на кожну дрібну зміну не обов’язкова.

## 7. Критерій готовності

Проєкт готовий до здачі, коли:
- усі 4 пункти працюють;
- програма не падає на типових помилках введення;
- калькулятор дотримується пріоритету операцій;
- гра правильно рахує бали;
- трикутник відповідає введеній висоті;
- правила високосного року перевірені на граничних роках;
- `dotnet build` проходить без помилок;
- репозиторій містить зрозумілу документацію;
- зроблені скриншоти виконання.
