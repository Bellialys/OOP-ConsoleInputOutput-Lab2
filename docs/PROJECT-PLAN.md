# План проєкту

## 1. Мета

Створити один консольний застосунок C#, який об’єднує чотири навчальні завдання. Користувач запускає програму, бачить заставку, переходить до головного меню, обирає потрібний модуль, виконує його та повертається до меню.

Принцип проєкту: **простий код, зрозуміла структура, коректні алгоритми, охайна взаємодія з користувачем**.

## 2. Технічні рішення

- Мова: C#.
- Платформа: .NET 8.0 LTS.
- Тип: Console Application.
- IDE: Visual Studio 2022 або VS Code.
- Сторонні NuGet-пакети: не потрібні.
- Кодування консолі: UTF-8 для коректного українського тексту.
- Основна гілка Git: `main`.

.NET 8 обрано замість попередньої/preview-версії .NET, щоб проєкт було простіше запускати на комп’ютері викладача.

## 3. Користувацький сценарій

1. Запуск програми.
2. Коротка заставка.
3. Натискання Enter.
4. Головне меню:
   - 1 — перевірка року на високосність;
   - 2 — побудова трикутника;
   - 3 — гра «Хто хоче стати мільйонером?»;
   - 4 — калькулятор;
   - 0 — вихід.
5. Виконання обраного завдання.
6. Пауза та повернення до головного меню.
7. Завершення програми через пункт 0.

Некоректний пункт меню не повинен завершувати програму.

## 4. Архітектура

### Program.cs
Точка входу. Відповідає за:
- налаштування консолі;
- заставку;
- створення доступних завдань;
- цикл головного меню;
- вибір модуля;
- коректний вихід.

### IConsoleTask
Мінімальний спільний контракт:
- `Title` — назва завдання;
- `Run()` — запуск завдання.

Це демонструє базове застосування поліморфізму без складної архітектури.

### LeapYearTask
Відповідає лише за введення року, перевірку введення та визначення високосності.

### TriangleTask
Відповідає за введення висоти та побудову числового трикутника за допомогою циклів.

### MillionaireTask
Керує п’ятьма питаннями, перевіряє відповіді, нараховує бали й завершує гру після першої неправильної відповіді.

### Question
Модель одного питання:
- текст;
- масив із 4 варіантів;
- номер правильної відповіді.

### CalculatorTask
Розбирає арифметичний рядок і обчислює його без `eval` та без `DataTable.Compute`.

### ConsoleHelper
Містить лише повторювані консольні операції:
- заголовок;
- пауза;
- безпечне читання цілого числа;
- повідомлення про помилку.

Алгоритми завдань у цей клас не переносяться.

## 5. Етапи реалізації

### Етап 0 — документація
- README;
- вимоги;
- план;
- тестові сценарії;
- коректний .gitignore.

### Етап 1 — каркас застосунку
- створити solution та .NET 8 console project;
- налаштувати UTF-8;
- реалізувати заставку;
- реалізувати головне меню;
- додати `IConsoleTask`;
- додати чотири модулі-заглушки;
- перевірити неправильний пункт меню.

### Етап 2 — завдання 1: високосність року
Логіка:
1. якщо рік ділиться на 400 без остачі — високосний;
2. інакше, якщо ділиться на 100 — не високосний;
3. інакше, якщо ділиться на 4 — високосний;
4. інакше — не високосний.

Контрольні значення: 1900, 2000, 2024, 2025, 2100.

### Етап 3 — завдання 2: трикутник
Для кожного рядка `i`:
- обчислити відступ;
- вивести число `i` рівно `i` разів;
- перейти на новий рядок.

Робочий діапазон висоти: 1–20. Це не змінює суті завдання, а лише захищає консоль від випадкового надмірного виводу.

### Етап 4 — завдання 3: мільйонер
- рівно 5 питань;
- 4 варіанти у кожного;
- одна правильна відповідь;
- стартовий рахунок 0;
- +100 за кожну правильну відповідь;
- неправильна відповідь завершує поточну гру;
- усі 5 правильних → 500 балів.

Введення поза 1–4 не рахується неправильною відповіддю — користувач просто вводить значення повторно.

### Етап 5 — завдання 4: калькулятор
Обов’язкова підтримка:
- `+`;
- `-`;
- `*`;
- `/`;
- пробілів між елементами виразу;
- правильного пріоритету;
- лівоасоціативного виконання операцій однакового пріоритету.

Приклад:
`5 + 5 * 10 + 4 / 2 - 3 = 54`.

Базовий алгоритм:
1. токенізувати рядок на числа та оператори;
2. перевірити правильність послідовності токенів;
3. виконати `*` та `/` зліва направо;
4. виконати `+` та `-` зліва направо;
5. вивести результат.

Обов’язково обробити ділення на нуль і некоректний синтаксис.

Дужки, степені та функції не входять до вихідного завдання й у першу версію не додаються.

## 6. Стиль коду

- Імена класів і методів — англійською.
- Текст, який бачить користувач, — українською.
- Один метод — одна зрозуміла відповідальність.
- Мінімум дублювання.
- Без «магічних» складних конструкцій, які важко пояснити на захисті.
- Коментарі лише там, де алгоритм справді потребує пояснення.

## 8. Критерій готовності

Проєкт готовий до здачі, коли:
- усі 4 завдання доступні з одного меню;
- програма не падає на типових неправильних введеннях;
- високосність правильно визначається для років, кратних 4, 100 і 400;
- трикутник має введену висоту;
- гра правильно завершується після помилки та рахує бали;
- калькулятор дотримується пріоритету й порядку операцій;
- `dotnet build` завершується без помилок;
- проєкт запускається у Visual Studio 2022 та через `dotnet run`;
- зроблено скриншоти виконання для здачі.
